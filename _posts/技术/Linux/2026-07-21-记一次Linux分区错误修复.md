`/dev/sda3`分区共有7.3T，但实际没用多少，所以想将空闲空间划出做新分区，但是在操作分区时错误，导致系统引导失效，无法开机

错误操作如下：
```bash
fdisk /dev/sda3
n
1
w
```

错误操作后没有再做任何操作，所以只有分区信息丢失，实际数据并没有并擦除，所以有恢复的可能。

# 2.修复步骤

主要修复思路是：
1. 找到分区头信息，进行恢复
2. 修复grub系统引导文件

额外准备一个PE启动盘，通常使用Iventoy+SystemRescue组合，Iventoy安装到U盘，在U盘中直接放入iso文件即可成功制作启动盘，并且U盘可以正常使用

# 2.1 初步尝试

```bash
# 1. 强制扫描物理卷（忽略损坏的头部）
pvscan --cache

# 2. 核心恢复命令：强制从物理硬盘末尾的元数据备份区恢复卷组
# 注意：klas 是你的卷组名（根据你之前的 lsblk 输出）
vgcfgrestore -y klas
# 直接指定物理设备，让系统自动找备份
vgcfgrestore -y --force /dev/sda3
```

但是系统没有做过备份，所以这一步相当于失败

# 2.3.2 重建标签和数据

`5XI005-4XrZ-iAyT-bEjo-cjjj-kBwp-wGBTWh`为`/dev/sda3`的id信息
`/tmp/klas_backup.cfg`为上面的文件

重建 PV 标签，并恢复数据
```
pvcreate --restorefile /tmp/klas_backup.cfg \
         --uuid 5XI005-4XrZ-iAyT-bEjo-cjjj-kBwp-wGBTWh \
         /dev/sda3

```

接下来只需激活卷组、删除无用的快照、挂载并修复引导。


# 2.3.4 激活卷组


```
vgchange -ay klas
# 删除快照（可选）
lvremove -y /dev/klas/snapshot0
lvremove -y /dev/klas/root_before_cluster_install
```
到这一步后一个阶段算是完成了，因为数据已经恢复，现在要解决引导开机的问题

# 2.3.5 挂载分区

```
mount /dev/sda2 /mnt/boot
mount /dev/sda1 /mnt/boot/efi
mount --bind /dev /mnt/dev
mount --bind /proc /mnt/proc
mount --bind /sys /mnt/sys
```

# 2.3.6 进入系统恢复grub文件

```
# 进入自己的系统（之前的操作都是system rescue中）
chroot /mnt /bin/bash

```

两种方式：
1.自动创建grub文件

```
# 重装 GRUB 到磁盘
grub2-install /dev/sda
# 如果 grub2-install 报错，尝试 grub-install /dev/sda

# 重新生成 GRUB 配置
grub2-mkconfig -o /boot/grub2/grub.cfg
# 若路径不同，常见的还有 /boot/grub/grub.cfg
```
2.手动创建
在`/mnt/boot`中找到系统镜像文件

```
insmod part_gpt
insmod lvm
insmod ext2
menuentry "Kylin Linux" {
    linux /vmlinuz-4.19.90-89.11.v2401.ky10.x86_64 root=/dev/mapper/klas-root ro quiet
    initrd /initramfs-4.19.90-89.11.v2401.ky10.x86_64.img
}
```

至此恢复完成
